# ADR-0011: Prisma 7 — driver adapters and external config

**Status:** Accepted
**Date:** 2026-07-26
**Deciders:** Lead architect

## Context

`prd.md` §17 specifies Prisma as the ORM, and ADR-0001 makes `libs/shared/database` its sole owner. Prisma 7 (7.9.0 at time of writing) changes two things that the PRD's Prisma-6-era assumptions do not account for:

1. **`url` is no longer permitted in the `datasource` block.** `prisma validate` fails outright:
   > The datasource property `url` is no longer supported in schema files. Move connection URLs for Migrate to `prisma.config.ts`.
2. **The runtime client requires a driver adapter.** There is no bundled query-engine binary connecting on its own; you pass an adapter such as `@prisma/adapter-pg` to the `PrismaClient` constructor.
3. **`.env` is no longer auto-loaded** by the CLI, so a connection string that "should" be present is simply absent, with a confusing downstream error.

These are not optional migrations — Prisma 7 does not start without addressing all three.

## Options considered

**A. Pin Prisma 6.** Keeps the familiar `url`-in-schema model and the bundled engine. Rejected: starting a greenfield project on the previous major means an unavoidable migration later, and Prisma 7's adapter model is the direction of the ecosystem.

**B. Adopt Prisma 7 as designed** — `prisma.config.ts` for CLI/migrate, `@prisma/adapter-pg` for runtime.

**C. Prisma 7 with a serverless-oriented adapter** (Neon, PlanetScale HTTP). Rejected for now: ADR-0001 runs the API on a persistent container, where a normal pooled TCP connection is the correct and cheapest choice. Revisit only if the API moves to a serverless runtime.

## Decision

**Option B.**

- `libs/shared/database/prisma/schema.prisma` declares only `provider = "postgresql"` in its datasource.
- `prisma.config.ts` at the repo root supplies the migrate/introspect connection string, the schema path, the migrations directory, and the seed command. It lives at the root because that is where the Prisma CLI looks; putting it elsewhere would require `--config` on every invocation. Schema _ownership_ still belongs solely to `libs/shared/database` (CLAUDE.md §8).
- `prisma.config.ts` imports `dotenv/config` explicitly, since Prisma 7 no longer loads `.env` itself.
- The runtime client is built by `createPrismaClient(connectionString)` in `libs/shared/database`, wrapping `@prisma/adapter-pg` over `pg`.
- **`createPrismaClient` is deliberately framework-free** — no Nest, no decorators. That is what keeps `libs/shared/database` safe to import from any scope without dragging a server framework into the graph. The Nest module managing its lifecycle lives on the API side with the first repository that needs it (M1).
- Generated output goes to `libs/shared/database/src/generated/prisma`, git-ignored, excluded from lint and from the library's `tsconfig.lib.json`, and regenerated by a `postinstall` hook so a fresh clone is never missing a client.

## Consequences

**Positive**

- On the current major from day one; no forced migration later.
- The connection string is supplied at construction, which makes the client trivially testable against a Testcontainers database (CLAUDE.md §12) — a real improvement over schema-embedded URLs.
- Adapter indirection means swapping to a serverless driver later is a one-line change in one file.
- No query-engine binary to ship, so container images are smaller.

**Negative**

- Two extra runtime dependencies (`@prisma/adapter-pg`, `pg`) and a root config file that is arguably ownership leakage from `libs/shared/database`. Accepted for CLI ergonomics; noted so nobody "fixes" it by moving the file.
- Connection pooling is now `pg`'s concern, so pool sizing is explicitly ours to tune. Must be set deliberately before production, not left at defaults.
- `prisma` (the CLI) pulls `@prisma/studio-core`, which drags React, Radix, and visx into the dev dependency tree. Harmless but noisy, and it briefly muddied a duplicate-React investigation.
- Much online Prisma material still assumes v6, so search results will mislead. Hence this ADR.

## Revisit when

- The API moves to a serverless or edge runtime — switch to the matching driver adapter (Option C).
- Connection-pool exhaustion appears under load; revisit pool configuration and consider a pooler such as PgBouncer.
- Prisma 8 arrives; check whether `prisma.config.ts` and adapter APIs changed again before upgrading.
